# 官方规则对齐：31.4.5

核查日期：2026-10-28。范围为当日官网普通 1v1 / FFA，无自定义 modifier、团队模式或活动规则。RL 暂时仅 1v1，训练和评估均为 2000 tick 截断。

目标为核查时官网实际部署的 **31.4.5**。客户端 URL、SHA256 固定在 [规则协议](../env/src/generals/protocol/rules.py)。仓库保留可离线运行的数值对照样例，不包含官网客户端源码。

### 关键语义变化

- **动作时序**：先同边界决策，后行动，最后增长。友军目标优先、非将军目标优先、来源兵力大者优先；相同时按旧 tick 奇偶交替席位顺序。追击链、反向移动与依赖环另作结算。
- **增长**：每 2 tick 已占城市／将军 +1；每 50 tick 全部已占格额外 +1。旧实现中城市没有第 50 tick 额外增长的假设已移除。
- **兵力与捕获**：0/1 兵来源不可行动；队列跳过这些项。严格优势才占领；继承兵力向上取整，0 保持 0。互相攻破将军的满足条件情形交换领土与将军，双方不淘汰、不记击杀。
- **迷雾**：公开“山或城市”的同一种提示，不公开隐藏兵力、归属或敌将军；转换将军位置的提示需要玩家看到过转换。终局视野、城市统计与 RL 特征同步开放。
- **离场**：立即淘汰但保留 50 tick 可增长、可捕获的领地；tick 0 的离场在 tick 1 生效。期满转中立，不通过 Arena 自己改地图模拟退出。
- **AFK / 时限**：1v1 的扩张检查在 tick 71，FFA 在 tick 121；满足扩张条件会取消警告。无有效行动计数超过 2000、旧 tick 超过 50000 触发官方自然结算。外部 2000 tick RL 截断不强行指定胜者。
- **FFA**：先区分有无击杀，再按存活／淘汰顺序，仍存活者按兵力、领土、席位排序。同 tick 淘汰不能简单并列。
- **特殊终态**：官方实时逻辑在同 tick 多人 AFK 时保留最后存活者缓存；即使终态全部 `alive=false`，仍可有赢家。Arena、RL 奖励与回放已覆盖此情形。

### 地图与 RL 输入

普通地图宽、高分别采样 `round(base + U² × (4 + P/2))`，`base=16+P+max(0,P-6)/2`；1v1 为 18–23，8 人 FFA 为 25–33。山脉／城市参数是 0–1 的官方滑块值，标准值 0.5，不是占棋盘的比例。标准城市兵力 40–50。

官方检查出生点与附近城市的可达性，**不要求全部空地连通**，因此删除旧生成器的全空地挖山修补。随机数实现与种子协议仍属本项目，不承诺相同数字种子与官网逐格一致。

RL 的 map bank 独立生成不同实际尺寸，再填充到 23×23 存储；14 个棋盘通道包含有效区域与迷雾障碍。填充格不能行动，公开统计按真实地图面积缩放，网络布局从统一 geometry 读取。K11 更新将军转换／交换后的记忆，不保留“将军位置永不变化”的假设。关闭 map bank 时每条 lane 有独立初图，reset 恢复各自初图。

训练与部署共用 `rl/policy/`：训练直接编码设备状态，导出包将 Arena 原始观测填充为同样的输入，再把动作还原到真实宽度。逐 tick 比较 `policy/single_obs/knowledge/action_mask` 和最终动作，CPU/CUDA 均要求一致。Arena 不导入 RL 特征代码。

## 使用与迁移

- 当前普通 Arena 默认配置：`arena/configs/league.json`；RL 模型对应的随机 1v1、2000 tick 联赛：`arena/configs/leagues/official_1v1.json`。
- 规则 ID 为 `generals.io-31.4.5-classic-v1`；Arena 联赛 schema 7、回放 schema 3，C++ SDK ABI 2。旧联赛／回放／9×9 权重使用对应归档源码，不增加旧规则兼容分支。
- 默认 RL profile 改为 `null`，按新规则生成 baseline＋WAIT 面板。移除内置 F03 9×9 校准配置及其专用加载入口，保留通用校准、外部配置加载和候选模型联合评估，不沿用旧参考分数。**新的校准、效果验收、显存预算和吞吐调优留待后续实验。**
- ViT1M、recent8、gamma 课程及原采样预算保留为起点；23×23 输入增加内存和计算量，尚未重新证明旧 16k/rank 配置的性能或效果。
