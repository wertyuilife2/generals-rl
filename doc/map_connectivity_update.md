# 全图连通修复记录

日期：2026-09-27。基线：`b3823a3`。

## 行为变化

原生成器只连接各主城；例如默认 25×25、4 人、seed=42 时仍有两个孤立格。现在要求所有非山脉格属于同一个四邻接连通块，空地和城市都必须能从主城到达。

实现位于 [mapgen.py](../env/src/generals_env/mapgen.py)：先从一个主城做普通 BFS。已经全图连通则原样返回；否则对其整个连通区域执行一次多源 0–1 BFS，以进入山脉的数量作为路径代价。所有孤立格共用父节点树回溯，已连接节点立即停止回溯，最后统一移除通路上的山脉。时间和辅助空间均为 O(H×W)。

城市与出生点沿用原来的随机选择；不删除任何原有非山脉格。地图目标山脉密度保持不变，修复后实际密度可能降低。本算法保证连通并优先复用已有通路，不保证全局挖山数量最少。

同一版本的同种子仍可复现；相同种子的最终地形可能与旧版本不同。路径缓存按最终地形摘要区分，动作录像保存初始数组，回放无需重新生成地图。

## 验证

```console
DISPLAY=:1 conda run -n generals-rl python -m unittest discover -s env/tests
```

106 项测试全部通过（2.738 秒），包括真实 Linux/X11 GUI 测试，无跳过。地图测试包括：

- 原先失败的默认 seed=42 孤岛回归。
- 2–8 玩家、不同种子和密度下，全部非山脉格可达。
- 15／25／35 预设、山脉密度 0／20%／40%、城市数量与状态不变量。
- 穷举 511 种至少含一个可通行格的 3×3 地形，验证连通、原有空地保留、确定性和重复修复不再改变地形。
- 单行、单列、厚山墙、对角接触、封闭区域及已连通地形保持不变。
- 优先选择少挖山的绕行路线，而非几何距离更短但需要多挖山的路线。

完整规则、控制器、观测、重放和 GUI 测试同时通过。

## 效率

复现命令（从仓库根目录、已安装环境包）：

```console
conda run -n generals-rl python env/benchmarks/benchmark_mapgen.py --samples 64 --seed 0 --baseline-ref b3823a3
```

CPU：Intel(R) Core(TM) i7-14700KF。Python 3.12.14、NumPy 2.5.2。每种配置使用 seed=0…63，每个方法先预热 3 张地图，随后交替执行新旧方法。计时范围是完整地图生成及状态验证，不含 AI 和 GUI；基线仅加载指定提交的地图生成模块，其余代码相同。

| 地图 | 玩家 | 山脉目标密度 | 旧版中位数 ms | 新版中位数 ms | 新版 P95 ms |
|---|---:|---:|---:|---:|---:|
| 15×15 | 2 | 20% | 0.812 | 0.174 | 0.182 |
| 15×15 | 2 | 40% | 0.812 | 0.164 | 0.173 |
| 25×25 | 4 | 20% | 6.299 | 0.368 | 0.378 |
| 25×25 | 4 | 40% | 6.320 | 0.337 | 0.363 |
| 35×35 | 8 | 20% | 28.876 | 0.680 | 0.744 |
| 35×35 | 8 | 40% | 28.789 | 0.603 | 0.737 |

提升来自取消逐主城重复搜索，以及避免搜索内层反复访问 NumPy 标量。该结果是本机样本测量，未做绑核或跨平台性能保证。原始统计和运行参数见 [map_connectivity_benchmark.json](map_connectivity_benchmark.json)。
