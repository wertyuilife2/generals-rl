# H200 scaling：22 项训练的效率与效果

本报告整理 **2026-10-14 已闭合的 22 项训练**，不是当前 HEAD 的性能测量。22 项有效 TRAIN 均正常退出，累计训练墙钟 **49.731 小时**、**10,898,898,944 个 fresh learner transitions**。在本批 9×9、双人、四基础 AI、每项约 1–3 小时的范围内，**ViT 1M dense 的效果与吞吐组合最好**；扩大到 10M/100M 没有超过它的预算内效果。这个结论不代表更大地图、更多训练量或更强对手下的能力上限。

## 范围、版本与计量

全部使用 8×H200、当前 learner 自对弈、每次 PPO 的 E=4 epochs；对手的 NN 决策计入运行耗时，但训练样本只计 learner 座，双方不能重复相加。模型的 1M/10M/100M 是 actor＋critic 总参数的配置档位。D=dense，P=pyramid。

| 版本 | Run | 运行时边界 |
| --- | --- | --- |
| A | F01–F14 | 旧源码归档 source122；Python 基础 AI 评估 |
| B | F15/R01 | C++ 基础 AI 评估初版；`68700da` |
| C | F16/P01–F22/P11 | C++ 评估及安全整数转换冗余扫描优化；`ada5b887` |

A/B/C 是历史执行版本，**C 不表示今天的代码**。跨版本结果可描述实际成本和效果，不能当作只改变 C++ 或某个超参数的受控 A/B。

N 为八卡合计的并行环境数，T 为每环境 rollout ticks，B 为全局逻辑 PPO minibatch 样本数。下表 **N/T/B 都写精确整数**，例如 `131,072/64/16,384`；不使用含混的“k 环境”。每卡环境数为 N/8，逻辑每卡 minibatch 为 B/8；物理 microbatch 只影响执行分块。fresh M 使用十进制百万。

| 速度列 | 分子 | 分母与排除项 |
| --- | --- | --- |
| 正式 | 独立基准中采集的 fresh learner transitions | 每次完整 collect＋GAE＋E4 更新的最慢 rank 同步时间之和；排除 warmup、周期评估和独立 profile |
| 训练计算 | 实际 TRAIN 的 fresh learner transitions | 实际采样／学习各阶段累计计时，采用 rank-max 口径；不是独立基准的重跑 |
| 训练墙钟 | 同上 | TRAIN summary 墙钟，包含同步评估等非训练开销；进程边界的初始化／收尾差异另记，不包含随后单独开展的对战实验 |

速度统一以 **千 transitions/s（×1,000）** 表示；这是完整 RL 计算吞吐，**不是仅 `env.step(action)` 的环境吞吐**。E4 的重复训练不算四份 fresh 数据。对每个 rank：`optimizer steps/轮 = 4×N×T/B`，总计 `4×fresh/B`；PPO 轮数与 Adam 步数不同。

## 同版本内的主要比较

变化由原始未取整数据计算，pp 为百分点。比较表只给观察值；单种子、训练量和评估节奏没有全部固定，不能直接作因果解释。

| 对照 | 配置变化 | 正式吞吐 | 墙钟吞吐 | best 总体/最弱变化 |
| --- | --- | ---: | ---: | ---: |
| F01→F02 | N 32,768→65,536；T32/B65,536 | +4.45% | +10.17% | +1.625/+3.5pp |
| F02→F03 | N 65,536→131,072；T32/B65,536 | +2.44% | +6.97% | +0.250/+0.5pp |
| F10→F12 | ResNet 1M，N16,384→65,536 | +9.14% | +0.43% | −30.750/−16.0pp |
| F19→F20 | N131,072/T64，B16,384→32,768 | +22.96% | +9.20% | −44.875/−45.5pp |
| F20→F21 | N131,072/T64，B32,768→65,536 | +10.16% | +22.71% | +40.750/+35.5pp |
| F19→F21 | N131,072/T64，B16,384→65,536 | +35.45% | +34.00% | −4.125/−10.0pp |
| F21→F22 | N131,072/B65,536，T64→128 | −0.0022% | −3.86% | −37.125/−39.5pp |

**增大 N 的吞吐收益逐渐饱和，学习收益不一致。** ViT 1M 的连续翻倍只带来约 4.45% 和 2.44% 正式吞吐增长；ResNet 1M 的相近 430M 样本中，N16,384→65,536 的 best 总体从 64.75% 降至 34%。后者的累计每卡 Adam 步数为 26,240/25,984/26,368，基本相同；变化较大的是重新采样和双方策略刷新的轮数，不能说大 N 只是“少训练了几倍”。

**增大 B 同时改变效率和优化过程。** F19/F20/F21 的正式吞吐为 135.6/166.7/183.6 千/s，而 best 最弱 AI 为 93/47.5/83%。B32,768 是明显低点，现有结果不支持单调的 batch—效果关系。逻辑 B 和每卡物理 batch 也同时改变；E4 的每样本复用次数未变，但每份 fresh 样本对应的 Adam 步数减少。

**T128 没有显示优势。** F21→F22 的 PPO 轮数 143→68，但每轮每卡 E4 Adam 步数 512→1,024；累计 73,216→69,632，只少 4.90%，与 fresh 样本减少一致，并非优化工作量减半。固定策略采样更久、重新采样频率更低是待验证解释。F19/F20/F21/F22 分别每 5/6/7/4 轮评估，选模时点也不同；这些配置共享部分比较 run，不能把三组 pair 当作独立重复证据。

**模型规模结果受空间组织和预算混杂。** ViT 1M 是 dense，而 10M/100M 是 pyramid；扩大容量时也改变了空间表示。1M/10M/100M 的本批最高 best 为 99.625%/91.125%/76.125%，但样本量、早停与版本不同，不能据此推断大模型的最终能力上限。ResNet 的弱结果优先要求检查 current/history 对手、KL/LR、最低训练量与早停；曾有 8 历史快照对手协议达到超过 90% 总体，这里的“8”不是观测 H8。既有审查没有定位明确的参数遗漏或 detach 错误，也没有证明所有数值实现无误。

## 同步评估与 GPU 利用率

下表是历史完整 TRAIN 中 C++ 评估 worker 的累计时间占比，不是将 Python baseline 的旧运行混进结论。

| Run | 完整评估次数 | 评估占 TRAIN 墙钟 |
| --- | ---: | ---: |
| F15/R01 | 17 | 48.15% |
| F16/P01 | 8 | 41.90% |
| F17/P05 | 15 | 35.94% |
| F18/P07 | 10 | 31.90% |
| F19/P08 | 21 | 38.01% |
| F20/P09 | 18 | 44.77% |
| F21/P10 | 20 | 38.73% |
| F22/P11 | 16 | 41.04% |

八项共 125 次评估、28,816.98 秒，占对应训练墙钟 **40.77%**；版本 C 的七项为 31.9%–44.8%。因此“同步评估仍是主要开销”成立，但不是整程超过一半。worker 时间含模型、环境、观测、加载和等待，`墙钟−计算` 也不能全叫 CPU 时间。

合并 C++ 后的独立复测中，P10 best 的原生 800 局 CLI 为 **120.375 秒**，同为 ViT 1M 的较弱 P11 为 **271.033 秒**，后者平均对局更长。profile 的热点是每 batch 全量状态对象重建及观测／特征处理；环境推进与动作指标只占 P10 完整进程约 2.5%。这些是当时 `ada5b887` 的诊断，后续批量观测／评估优化不能反向改写本批历史墙钟。

22 项没有一项通过“整程每卡平均 NVML≥80%”验收。P11 GPU0 均值约 58.3%，其余约 95%；其余 rank 的高 NVML 可能包含等待，不是有效 PPO 工作或 SM occupancy。完全消除历史 40.77% 评估成本的理想上限约 1.69×，不是异步实现已取得的加速。

## 结论与适用边界

| 选择目的 | 这批数据支持的候选 | 限制 |
| --- | --- | --- |
| 使用已训练的最高 baseline checkpoint | F03 best12，99.625%/99.0% | 选 checkpoint，不等于证明当前源码重训可复现 |
| 版本 C 内质量优先 | F19/P08，98.0%/93.0%，墙钟83.2千/s | 约897.6M样本，单次训练 |
| 版本 C 内效率与质量折中 | F18/P07，95.375%/88.5%，墙钟102.2千/s | 较早停止、约477.1M样本，不能与满预算等量比较 |
| 版本 C 内正式吞吐优先 | F21/P10，183.6千/s，93.875%/83.0% | 增大B的质量代价没有跨种子确认 |
| 超过200千/s的历史路线 | F04，204.3千/s，98.625%/96.0% | 属版本A，不能直接作为当前版本承诺 |

这里的 F03 是后续消融的固定参考，不把重复使用同一参考模型或共享对照 run 算作多个独立控制。后续默认方案应由固定预算、多种子消融确定，本报告只提供 scaling 阶段的选择依据。四个基础 AI 对 ViT 1M 已接近天花板；更大地图、更强规则对手、独立测试地图和多训练种子仍是外推前提。
