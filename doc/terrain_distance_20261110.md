# Temporal + HL128：路径与 episode 时限消融

2026-11-10，分支 `codex_dev_clean`。原始配置、冻结源码、日志和测量保存在
`outputs/experiments/terrain_distance_20261110_actual01/`；[动态结果与曲线](terrain_distance_20261110_results.md)。
本轮 v30–v32 属于 2026-11 的 H200 消融编号，不是早期同名网络版本。

## 配置与公平比较

三组从头训练，单种子 `2026102901`，8×H200，每卡 2,048 个真实对局／4,096 条玩家轨迹，
T512/E1/M256。每卡逻辑和物理 minibatch 均为 8,192；224 轮，共 3,758,096,384 条新玩家样本，
每组 57,344 次 optimizer 更新。不筛选 advantage，不混入历史池或规则对手。

9×9 地图课程沿用旧 v11/v24–v29：按全局真实 board ticks，在 71,303,168–306,184,192 间
从易图推进至正式地图。继续使用同一地图生成缓存。mapgen、map_sampling 源码 SHA256 相同；
map_curriculum 仅更新了两处计数单位的说明文字，地图内容和课程阈值未变。

网络为 early_shared ViT：width128/depth4/heads4，patch1，actor/critic 共用 Transformer，
critic 额外读取特权地图。沿用分次前向／反向与共享梯度累加、BF16、compile、inference chunk2048。
temporal 特征保留8帧变化、最后观察到的敌军兵力及公开比分EMA；不启用半兵动作去重。
HL-Gauss 使用128个线性中心、支持[-1,1]、sigma=.04、value_loss_coef=.01；关闭 value clipping。
胜负奖励±1，其余为0；gamma=1、lambda=.95；KL自适应学习率及PPO监控沿用旧配置。

| Run | 训练时限 | 主要评估时限 | 相对本轮基线的唯一实验设置变化 |
|---|---:|---:|---|
| v30_9x9_temporal_hl128 | 2048 | 2048 | temporal＋HL128组合基线 |
| v31_9x9_temporal_hl128_4096 | 4096 | 4096 | episode时限 |
| v32_9x9_temporal_hl128_paths | 2048 | 2048 | 两个地形最短距离通道 |

时钟特征遵循已有实现 `tick/max_episode_steps`，因此4096组也改变了该归一化分母；
长期记忆的age尺度仍为2000，避免额外改变特征方案。超时仍是truncation并使用reset前观测bootstrap。
旧 v25/v28 的训练上限2000、主评估上限1024，与本轮并不完全相同；作为历史参考而非严格单变量对照。

## 两个路径通道

新增 `feature_set=temporal_paths`，保留temporal全部输入和动作空间，附加：

1. 每格到己方大本营的最少四邻域移动步数。
2. 每格到最后观察到的敌方大本营的最少移动步数；尚未发现时不提供真实位置。

图只使用本座的地形记忆、官方公开的迷雾障碍提示和有效地图范围。已知山脉与padding阻断；
未辨明的“山或城市”提示保守地视为障碍，确认地形为平地／城市后允许经过。
城市不额外收费；兵力、归属、战斗和增长不影响边权。因未知山/城的歧义，这不是全知地形的精确距离。
敌方大本营重新进入迷雾后仍用最后发现位置；重新观察会更新或清除旧身份。

有限距离编码为 `log1p(d)/log1p(canvas_cells)`；已知目标但不可达／障碍格为-1，
目标未知或身份不唯一为-2。无需额外有效性通道，不把“敌王未发现”与“不可达”混为一谈。
不修改reward，不屏蔽绕行／撤退动作，不堆叠路径历史。

实现拆分在 `policy/paths.py`（语义、CPU参考与缓存）和 `policy/paths_cuda.py`（批量GPU内核）。
每个玩家lane的每个目标一个GPU程序，比较本座阻断图和两个目标的缓存键；只有相关地形知识或目标改变才计算该距离场。
BFS迭代在单个GPU程序内进行，直到收敛，不按宽＋高错误截断，不逐环境调用Python或回传CPU。
每局、每座缓存隔离；reset、导出推理容量增长和搜索clone保留相应语义。

路径通道填入原temporal的padding位置，保留前37个有效通道的索引。输入仍对齐为40通道，
token数、参数量和随机初始化均不变。网络前向已读取两个非零新通道，并非在输入过程中丢弃它们。

## Rollout 与性能检查

路径在行动边界由当时的知识生成，随knowledge存入rollout；PPO gather只解码对应时间点的快照，
不访问后来更新的地图或缓存。沿用FP16行动前量化和无损解码，两个新通道不进入历史堆叠。
T512、每卡4096玩家轨迹、9×9的理论额外观测存储是
`512×4096×81×2通道×2字节 = 0.6328125 GiB`，还需以完整预检的buffer和峰值统计核对。

CPU/GPU对照测试覆盖9×9、23×23和非正方形地图，包括超过宽＋高长度的蛇形通路；
同时测试迷雾隔离、缓存更新、partial reset、旧PPO快照、同初始化／原通道索引、训练恢复与导出推理。
本地还执行了temporal_paths＋HL128的真实CUDA训练与timeout循环。

每组正式前以真实环境数、T512、完整batch执行3轮预检，再用导出actor对七对手做smoke。
预检不计入224轮正式样本。完整训练记录rollout/PPO分项秒数、玩家与board吞吐、全rank最大
allocated/reserved、allocator retry、观测buffer字节以及现有PPO／价值／共享梯度诊断。

GPU上其他任务继续运行；本轮三组依次执行，允许与外部任务共存。启动要求每卡至少28GiB可用，
本轮训练进程allocator上限为总显存22%，预留同步评估空间。记录GPU利用率和外部进程变化，
不把共享机器吞吐当成独占性能，也不以不同时段的小幅差距断言优化收益。
每组只保留有限近期checkpoint及最佳快照，磁盘不足时停止本实验的后续启动。

预检中发现本机与H200的Triton版本不同，首版GPU内核在H200编译失败。已改为有界循环、收敛后跳过松弛，不修改工具链；H200微测、8项专项测试和三组完整预检均已通过。9×9/4096玩家lane下，缓存命中约0.043ms、全部目标重算约0.120ms，输出编码约0.049ms；这些是共享GPU上的内核微测，完整训练增量以下面的预检为准。
