你的任务是研发世界最强的 Generals.io 启发式算法，在最终的测试中你可能与其他最厉害的算法一较高下。

本轮预算为 60 分钟墙钟时间，包含资料阅读、研发、编译、实验、正式评测和交付。
最终交付是 heristic/<run_id>/ 下的 C++ 策略代码，以及该版本最后一次 Arena 全量评测成绩。
研究目标包括对不同对手、人数和地图的通用竞争力，不止于击败现有 baseline。
不能只凭本地几个对手的结果宣称已经世界最强。

算法设计、研究路线、实验安排和时间分配由你自主决定。
你可以挑战 baseline、进行自我对战，以及与自己的历史版本比赛。
Arena 提供全部比赛、计时、记录和全量评测服务；你只负责实现符合接口的 C++ 策略。

3. 实现与信息约束

算法必须使用单线程 C++ 实现。无需自己实现 Python 适配、比赛循环、评分、计时或录像系统。
每个席位使用独立实例，只能使用 Arena 给出的合法观测、自身历史信息和独立随机状态。
不能访问隐藏棋盘、地图生成种子、其他控制器内存，也不能在席位之间共享局内信息。
可变策略状态保存在各自 instance 中，全局数据只存放只读常量。

baseline 仅作为黑盒对手。允许通过 Arena 调用，不阅读其源码、实现细节测试、
历史版本、其他位置的源码副本，也不进行源码反射、反编译或反汇编。
自己的算法不能通过继承、包装或调用 baseline 来替自己决策。

不修改 env、baseline、RL、Arena 的实现或 SDK，不改变规则、计时和评分口径。
不另写游戏后端；比赛和评测均使用 Arena 提供的接口。

每次决策的硬上限为 10ms，由 Arena 独立计时和判定。
预算计入 C++ 决策及其原生保护调用开销，不计 Arena 的观测构造、通信、游戏引擎更新或赛前创建。
首次决策、所有地图与人数都适用。禁止创建线程或子进程，禁止后台计算和修改计时器/信号处理。
任何一次超时都不合格，不能用平均耗时或分位数代替，不得漏报、排除慢局或规避计时。
不使用外部文件、网络、外部进程或未登记实现承载额外决策。

4. Arena 接入与自由测试

下面是实际可用的接口，不规定你的研究方法。命令均从项目根目录运行。
无需创建研究会话、提前注册或编写 entrant JSON，直接提供源码路径即可。

策略可以是单个任意命名的 .cpp，也可以是含多个 .cpp 的目录。
单文件入口自动收集本地 .h/.hpp 依赖；多文件目录中的所有 .cpp 联合编译为 C++17 共享库。
#include "arena_policy.h" 所需的官方头文件由 Arena 自动提供。
同场所有策略与 env CPU 引擎在同一个比赛进程内顺序执行，每席位一个实例。
策略之间没有逐决策 IPC，不启停策略进程，也不创建策略线程。
策略提供三个 C ABI 函数，具体类型由头文件定义：

extern "C" void *arena_create(int player, std::uint64_t seed, const char *params_json);
extern "C" std::int64_t arena_act(void *instance, const ArenaObservation *observation);
extern "C" void arena_destroy(void *instance);

arena_create 在赛前收到席位、策略种子和固定参数，没有地图信息；创建上限为 2 秒。
arena_act 收到合法局部观测和上一动作的结果反馈。
返回 WAIT=0，或 arena_move(source, direction, half)。方向上/右/下/左为 0/1/2/3。
观测指针仅在当前调用中有效。实例、进程和销毁由 Arena 管理。

自由测试示例：

.venv/bin/generals_arena run \
  --player baseline/aggressive \
  --player heristic/<run_id>/policy.cpp \
  --player heristic/<run_id>/policy.cpp \
  --size auto --games 100 --seed 42

每个 --player 是一个实际席位，须给出 2–8 个。允许重复，同一地图会轮换席位。
内置黑盒对手名称：baseline/random、baseline/aggressive、baseline/expansion、baseline/defensive。
历史自身版本可以用旧源码路径、policy/<完整版本哈希> 或 @已提交的正式别名指定。
纯自我对战只需给多个席位指定自己的策略。

--size auto 按人数使用正式地图分布；也支持 20x25 固定宽高，或 15:35 随机宽高范围。
--games 指定总局数；--seed 指定随机种子。
同一请求重复执行会恢复进度或读取已有结果，需要新样本时改变 seed。
可选 --params 参数.json，为所有源码路径玩家设置同一个固定参数对象。
使用已保存的 policy/<版本> 或 @别名 时保留该版本原来的参数。

命令返回 JSON，包含每种策略的版本哈希、按人数的名次/夺冠率/两两名次得分、计时和失败信息。
数据自动保存在 outputs/arena/native_1000/runs/<run_id>/；report 字段给出报告路径，
league_directory 字段给出对局和录像数据库目录。可选 --output 目录 导出报告及录像数据库。
自由测试不影响正式榜单，不占正式全量评测次数，但计入 60 分钟总预算。
纯同版本自我对战的两两得分为 null，不能当作实力提升证据。
查看自由测试回放可用 generals_arena serve <league_directory> --port 8087 --no-worker。

5. Arena 全量评测（最多三次）

本轮研究最多进行 3 次正式全量评测，每次固定 1000 局；不要求用满三次。
该次数限制是本次任务要求，即使通用 Arena 工具允许更多提交，也不得超过。
私有测试次数不限，但所有工作均计入 60 分钟总预算。

.venv/bin/generals_arena commit heristic/<run_id>/policy.cpp \
  --name "<模型名>-<自选单词>-v1"

多文件策略将文件路径替换成对应源码目录。固定参数通过可选 --params 参数.json 提交。
Arena 自动快照源码及参数、编译、进行 8 局接口预检，然后登记到正式联赛，
串行执行该版本的 1000 局比赛，更新统一 rating 并保存全部录像和计时记录。
正式工件由 Arena 自己保存，后续修改开发工作区不会影响已提交版本。
同一版本重复执行 commit 恢复原任务，不重复计分；不同实现使用新版本别名。
预检通过后开始正式任务即计入一次全量评测；之后中断或失败仍占一次。
不能把同一版本换个名字重复提交，也不能另建正式联赛绕过三次限制。
已有自身违规记录的版本不能提交，违规失败不能通过重试洗掉；修复后提交新版本。

完整评测的验收条件：报告 ok=true、completed_games=1000，
超时与错误均为 0，榜单和回放可读取，并能继续参与后续及人类比赛。
注册、入队或启动后台进程都不算完成。

最终成绩以最后一次全量评测为准，不从多次成绩中挑选最高分。
最终交付的策略源码及固定参数必须与该次评测的版本一致，不能用旧版本成绩代表修改后的代码。
如果最后一次评测未完成或发生违规，必须如实注明，不能用更早的成绩代替。

查询任务进度：.venv/bin/generals_arena status
正式网页：http://localhost:8086，已有服务无需重启。
