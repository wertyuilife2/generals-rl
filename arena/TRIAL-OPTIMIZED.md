## 性能与行为校验

本轮主要改动：

- 最近 16 个目标使用部分选择，保持距离与格子编号的破同分顺序，避免全图排序。
- 缓存与地形无关的邻接关系；BFS 使用玩家自己的记忆，保持上、右、下、左的寻路顺序。
- 使用掩码复制可见记忆，减少临时数组。
- Arena 复用引擎每 tick 已计算的统计，用两次轴向扩张构造同样的 3×3 视野，避免每个玩家重复计算全局统计。

固定 **8 人、35×33、1944 tick**，地图种子、控制器种子、完整动作和每个 tick 的状态摘要一致。
各运行三次，取中位数：

| 实现 | 中位耗时 | 每秒 tick |
| --- | ---: | ---: |
| 优化前 `a73a024` | 3.896 秒 | 499 |
| 本轮优化后 | 2.445 秒 | 795 |

同轨迹约 **1.59 倍**提速，耗时下降约 **37%**。
两者的完整录像内容 SHA-256 均为
`9d7f3f4a21c338a28a86b234361b6f5cc47f62348e30b613b44703fdcd7b5ede`。
上一轮的 45×41、3000 tick 黄金轨迹也保持一致，本轮三次中位耗时 3.731 秒。

上一轮 1000 局耗时 489.7 秒，本轮为 194.6 秒；两轮地图尺寸、赛程及总 tick 数不同，
不能把整个批次的时间差全部归因于代码优化。上表的同轨迹测量用于比较代码性能。

验证结果：

- **1000 / 1000 局**录像重新执行，全部 **1,584,005 tick** 状态摘要通过，校验耗时 17.2 秒。
- SQLite 完整性检查通过；从结果重新计算的评分与榜单完全一致。
- 81 项 Python 测试、15 项子测试及 14 项 JavaScript 测试通过。
- 对照测试覆盖观测的全部字段、只读性、跨玩家隔离、大整数兵力，以及寻路和最近目标选择的破同分行为。
- HTTP 检查覆盖前端模块、元素引用、榜单和包含 3001 帧的完整回放；旧服务仍保留 1002 局记录。
